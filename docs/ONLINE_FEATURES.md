# 랭킹·도전과제

## 실행과 서버 구성

기본 운영 방식은 **호스트 노트북 + Spring Boot 기록 서버 + HTTPS 터널**입니다. 호스트는 `SERVER.cmd` → `TUNNEL.cmd`, 본인 게임은 `PLAY_HOST.cmd`로 실행합니다. 팀원은 `PLAY.cmd`에서 전달받은 주소로 접속하며 별도의 서버나 DB 계정을 준비하지 않습니다. [자세한 실행·DB 백업 안내](HOSTED_SERVER.md)

게임은 libGDX Windows GUI, 연결 창은 Swing입니다. 연결 창은 기존 게임 그림·폰트·색·문양을 공유하고, 주소 입력·연결 상태·실패 후 재시도·오프라인 실행을 제공합니다. HTTP 요청은 GUI를 막지 않으며 응답 처리는 게임의 렌더 스레드로 전달합니다.

운영 DB는 서버 폴더의 `data/deadlight.mv.db`입니다. 파일 기반 H2와 `CREATE TABLE IF NOT EXISTS`를 사용하므로 정상 종료 후 재시작해도 기록이 유지됩니다. 서버를 끄면 조회·등록이 중단되며 다시 켜면 기존 기록을 읽습니다. 터널 주소가 바뀌어도 한 호스트의 DB와 클라이언트 프로필은 유지합니다. DB 없이 다른 폴더에서 서버를 켜면 별개의 랭킹이 만들어집니다.

## 클리어 시간 랭킹

전체 모험과 지역 연습 기록을 구분하고 게임 규칙 버전·시작 지역별로 조회합니다. 클리어 시간을 오름차순으로 비교하며, 플레이어별 최고 기록을 표시합니다. 이름은 영문 A–Z 세 글자 이니셜입니다. 서버는 클리어 여부, 기록 범위, 규칙 버전과 보조 기능 사용 여부 등을 확인합니다.

클리어 결과는 업적 판정을 위해 비공개 상태로 먼저 전송합니다. 이니셜 화면에서 **기록 등록**을 선택해야 공개 랭킹에 표시됩니다. 공개 등록을 건너뛰어도 달성한 업적은 저장됩니다. 로비 랭킹의 **기록 등록**으로 최근 클리어를 나중에 등록할 수 있습니다.

## 도전과제

전체 모험 완료 결과를 서버가 판정하고 최초 달성 일시를 보관합니다. 지역 연습으로는 해금되지 않으며 능력치 보상은 없습니다.

- 첫 여정의 끝: 첫 클리어.
- 꺾이지 않는 여정: 재도전 0회로 클리어.
- 물약 없는 순례: 포션 0회로 클리어.
- 닿지 않는 그림자: 받은 피해 0으로 클리어.

## 플레이어와 미전송 기록

별도 회원가입 없이 PC에 플레이어 ID와 접속 토큰을 저장합니다. 서버에는 토큰 원문 대신 SHA-256 해시를 보관합니다. PC의 온라인 설정을 지우면 새 플레이어가 됩니다. 토큰을 다른 사람에게 전달하지 않습니다.

운영용 온라인 프로필 `deadlight.hosted.online`은 같은 호스트의 주소가 바뀌어도 동일하게 사용합니다. 기존 클라우드의 주소별 프로필과 GameTest 프로필은 보존하고 자동으로 합치지 않습니다. 게임 설정의 기존 저장 방식도 유지합니다.

연결 실패 시 미전송 클리어는 로컬 outbox에 보관하고 재시도합니다. **오프라인 실행**에서는 HTTP 요청을 보내지 않으며 다음 온라인 실행에서 전송할 수 있습니다. 같은 기록 UUID를 다시 보내도 기록·업적은 중복 생성되지 않습니다. 같은 UUID로 기록 내용을 바꾸면 거부합니다. 이미 등록한 플레이어의 접속 토큰은 다른 토큰으로 덮어쓸 수 없습니다.

## 소스·실행본과 검증

팀원은 GitHub 소스를 Gradle 프로젝트로 열거나 `BUILD_PORTABLE.cmd`로 만든 Java 포함 Windows ZIP을 사용합니다. ZIP에는 DB·접속 토큰·실제 터널 주소를 포함하지 않습니다. 소스 커밋에는 런타임·게임 JAR·ZIP·DB·도구 실행 파일을 넣지 않습니다. 고정 버전 cloudflared는 호스트의 첫 터널 실행 때 다운로드하고 체크섬을 검증합니다.

기본 검증 명령은 `gradlew.bat core:test lwjgl3:test server:test`입니다. 실제 파일 기반 SQL·HTTP 테스트로 두 사용자 랭킹 공유, 업적, 중복 등록 방지, 서버 재시작 후 기록 보존을 확인합니다. 클라이언트 테스트는 오프라인 미전송 기록과 터널 주소 변경 후 동일 플레이어·outbox 유지도 확인합니다.

## 기존 클라우드 구성

`Dockerfile`, `render.yaml`, PostgreSQL·MySQL 프로필은 선택 가능한 서버 배포 구성으로 남습니다. 현재 `PLAY.cmd`는 과거 Render 주소에 자동 접속하지 않습니다. Render·Neon 기록, 이전 사용자 홈의 `.deadlight/server` DB, GameTest의 DB를 운영 DB로 자동 이전하지 않습니다.

클라우드 배포를 별도로 유지한다면 비밀번호는 서비스의 비밀 환경변수로만 설정합니다. 이 프로젝트를 수정하는 것만으로 외부 Render·Neon 서비스가 중지되거나 삭제되지는 않습니다. 기존 서비스의 자동 배포가 연결되어 있으면 Push 시 배포가 시작될 수 있으므로 실제 서비스의 설정에 맞춰 관리합니다.
